## 1. 이 서비스로 할 수 있는 일

법령이나 제품 배합이 바뀌었을 때 다음을 근거 조문과 함께 알려 줍니다.

- 어떤 제품의 MSDS를 고쳐야 하는지
- MSDS의 몇 번 항목을 어떻게 고쳐야 하는지
- 한국산업안전보건공단에 다시 제출(재제출)해야 하는지

필요하면 **개정 초안**까지 만들어 담당자 승인을 기다리고, 승인하면 제품 MSDS에 반영합니다(시험 기능).

에이전트는 판단을 돕는 도구입니다. 다음 세 가지는 항상 지켜 주세요.

1. **최종 판단은 담당자가 합니다.** 답변의 근거 조문을 직접 확인한 뒤 결정하세요.
2. **공단 제출은 자동으로 하지 않습니다.** 승인 후 확정된 MSDS로 담당자가 직접 제출합니다.
3. **"확인 필요"라고 적힌 부분은 에이전트가 원문으로 확인하지 못한 내용입니다.** 사실로 쓰기 전에 직접 확인하세요.

## 2. 빠른 시작 — 처음 써 보는 순서

서버가 켜져 있어야 합니다. 꺼져 있으면 운영 담당자에게 요청하거나 [부록 A](#부록-a-서버-켜기끄기-운영-담당자용)를 보세요.

1. 브라우저에서 **`http://localhost:8000/`**을 엽니다.
2. **영향 분석** 탭에서 변경 사건(예: `U-02 T-20 톨루엔 함유량 변경`)을 고릅니다. 영향 제품과 고칠 항목 표가 바로 나옵니다.
3. 표에서 **변경 전·후 보기**를 눌러 MSDS가 어떻게 바뀌는지 확인합니다.
4. **AI 판정·개정 초안 만들기**를 누릅니다. 10~20초 뒤 근거 조문이 담긴 판정과 개정 초안이 나오고, 승인 대기 번호(`REQ-xxxx`)가 붙습니다.
5. **승인함** 탭으로 가서 개정 초안과 **현재 MSDS → 변경 후 MSDS** 비교를 검토합니다.
6. 문제가 없으면 **승인하고 초안 확정**, 고칠 점이 있으면 사유를 적고 **반려**를 누릅니다.
7. 승인했다면 **새로고침해서 반영된 MSDS 보기**를 눌러 **제품 MSDS** 탭에서 바뀐 내용을 확인합니다.
8. 확정된 MSDS로 공단 제출은 담당자가 직접 합니다.

궁금한 점은 언제든 **어시스턴트** 탭에서 문장으로 물어보세요(4장).

## 3. 화면 사용법 (탭 4개)

화면 위쪽의 탭을 눌러 이동합니다. 화면의 모든 버튼은 내부적으로 같은 질문 창구(`POST /query`)를 씁니다.

### 3.1 영향 분석 (대시보드)

| 부분 | 쓰는 법 |
|---|---|
| 변경 사건 선택 | 사건을 고르면 **사건 내용**과 **요약 카드**(점검 제품·개정 필요·재제출 대상·영향 없음)가 바로 나옵니다 |
| 제품 × MSDS 항목 표 | 제품마다 고칠 항목과 재제출 여부를 보여 줍니다. **변경 전·후 보기**를 누르면 그 제품의 MSDS 변경 전과 후를 나란히 보여 줍니다 |
| AI 판정·개정 초안 만들기 | 근거 조문 설명과 승인용 개정 초안을 AI가 만듭니다. 결과는 아래에 나오고 승인함에 대기 건이 추가됩니다 |
| 법령 가져오기 (오른쪽 위) | 국가법령정보센터에서 최신 조문을 다시 받습니다(7장). 옆에 현재 법령 기준일이 보입니다 |

- 표와 변경 전·후 문서는 등록된 변경 사건 데이터로 **규칙에 따라 바로 계산**합니다(AI를 쓰지 않아 즉시 나옴).
- '유독물질' 삭제처럼 새로 적을 표기가 정해지지 않은 부분은 **확인 필요**로 표시하고, 안전보건공단 자료를 참고값으로 보여 줍니다.

### 3.2 제품 MSDS

- 제품을 고르면 MSDS **1·2·3·15번 항목**, 성분별 **안전보건공단 물질 정보**(GHS 분류·화학물질관리법 규제), **이 제품에 영향을 주는 변경 사건**을 보여 줍니다.
- 영업비밀 성분과 담당자 연락처는 가려서 보입니다.
- 승인으로 MSDS가 바뀌었다면 개정판 번호와 개정일이 바뀐 값으로 보입니다.

### 3.3 어시스턴트

- 아래 입력창에 질문을 쓰고 **보내기**를 누르거나 Enter를 누릅니다. 줄을 바꾸려면 Shift+Enter.
- 예시 질문을 눌러 바로 써도 됩니다. 질문 방법은 4장을 보세요.
- 답변마다 **근거**(조문 원문 등)와 **처리 단계**를 펼쳐 볼 수 있습니다. 근거에는 '현행 법령', '시행 예정', '제품 MSDS', '판정 규칙', '서비스 정책' 같은 표시가 붙습니다.
- 개정이 필요한 질문이면 답 끝에 승인 대기 번호가 붙고 승인함에 추가됩니다.

### 3.4 승인함

- 탭 옆 숫자가 **승인 대기 건수**입니다.
- 각 건에서 **개정 초안**과 **현재 MSDS → 변경 후 MSDS 비교**(지워진 내용은 빨간 줄, 새 내용은 초록색)를 봅니다.
- **확인 필요 ⓘ** 배지에 마우스를 올리면 사유가 보입니다. 이런 항목은 대체 표기를 입력해야 승인됩니다(5.1).
- **승인하고 초안 확정** 또는 **반려**(반려 사유 필수)를 누릅니다.
- 화면을 열 때 **서버에 남아 있는 승인 대기 건을 자동으로 불러옵니다.** 다른 브라우저에서 만든 건, 서버를 다시 켠 뒤의 건도 보입니다. 다른 곳에서 이미 처리한 건은 '서버에 없음'으로 바뀝니다.

## 4. 이렇게 물어보세요

어시스턴트 탭이나 [부록 B](#부록-b-화면-없이-요청하기)의 방법으로 질문합니다. 변경 사건은 `U-번호`, 제품은 `P-번호`로 부르면 가장 정확합니다.

### 4.1 법령·제도 질문

| 예시 질문 | 받는 답 |
|---|---|
| MSDS 내용이 바뀌었을 때 다시 제출해야 하는 사항은? | 재제출 대상 3가지와 근거(시행규칙 제159조제1항) |
| 변경사항을 반영한 MSDS는 언제, 어디에 제출하나요? | '지체 없이', 공단에 제출(시행규칙 제159조제2항) |
| 이미 제품을 받아 간 고객사에도 새 MSDS를 줘야 하나요? | 제공 의무와 근거(산업안전보건법 제111조) |
| 사업장에서는 MSDS를 어디에 두어야 하나요? | 게시·비치 장소와 근거(산업안전보건법 제114조) |
| 화학물질관리법에 아직 '유독물질' 정의가 있나요? | 삭제 여부와 시행일 |

### 4.2 제품·성분 조회

| 예시 질문 | 받는 답 |
|---|---|
| 톨루엔(108-88-3)이 들어간 우리 제품은? | 해당 제품과 제품별 함유량 |
| P-006에 벤젠이 들어 있나요? | 들어 있는지 여부와 실제 구성성분 |
| P-003 담당자 전화번호 알려줘 | 가려진 연락처(예: 010-****-7890) |

성분은 이름이나 CAS 번호 어느 쪽으로 물어도 됩니다.

### 4.3 변경 사건 영향과 개정 판정

| 예시 질문 | 받는 답 |
|---|---|
| U-01 규제 변경을 반영하려면 어떤 제품을 고쳐야 하나요? | 영향 제품, 고칠 항목, 재제출 여부, **개정 초안(승인 대기)** |
| U-02 배합 변경 후 P-002 MSDS를 다시 제출해야 하나요? | 재제출 판정, 변경 전→후 값, **개정 초안(승인 대기)** |
| 톨루엔 관련해서 바뀐 규제 있어? | 관련 변경 사건과 영향 제품 |

| 구분 | 내용 |
|---|---|
| 제품 | P-001 클린솔브 A-100, P-002 한빛 신너 T-20, P-003 포르마-클리어 F-5, P-004 에코코트 W-30, P-005 벤조-프렙 B-1, P-006 알코-와이프 E-70 |

## 5. 개정 초안 승인과 반려

고쳐야 할 MSDS가 있으면 에이전트가 개정 초안을 만들고, 답변 끝에 이렇게 안내합니다.

> 개정 초안은 담당자 승인 대기 상태입니다 (REQ-3DDB). 확정·제출은 승인 후에만 진행합니다.

`REQ-` 뒤의 번호가 요청 번호입니다. 화면에서는 승인함 탭의 버튼을 쓰고, 문장으로 처리하려면 다음을 보냅니다.

| 하려는 일 | 보낼 문장 | 결과 |
|---|---|---|
| 승인 | `승인 REQ-3DDB` | 초안을 확정하고 **제품 MSDS에 반영**합니다(5.2). 공단 제출은 담당자가 직접 합니다 |
| 반려 | `반려 REQ-3DDB 함유량을 시험성적서와 다시 맞춰 주세요` | 초안을 확정하지 않고 사유를 기록합니다. MSDS는 바뀌지 않습니다 |

- 반려할 때는 **사유가 꼭 필요합니다.** 사유 없이 보내면 다시 요청합니다.
- 요청 번호는 대소문자를 가리지 않습니다.
- 서버를 다시 켜도 승인 대기 건은 남아 있습니다.
- 이미 처리했거나 없는 번호를 보내면 "승인 대기 건이 없습니다"라고 안내합니다.

### 5.1 '확인 필요' 항목이 있는 승인

U-01('유독물질' 정의 삭제)처럼 새로 적을 표기를 에이전트가 정할 수 없는 항목은 **확인 필요**로 표시됩니다. 이런 항목은 담당자가 대체 표기를 입력해야 승인됩니다.

- **화면**: 승인함에 '확인 필요 항목의 대체 표기' 입력칸이 나오고 **추천 문구**가 미리 채워져 있습니다. 추천 문구는 안전보건공단 단일물질 자료의 화학물질관리법 규제 항목입니다. 사유는 **확인 필요 ⓘ** 배지 툴팁과 아래 상자에 적혀 있습니다. 그대로 두거나 고친 뒤 **승인하고 초안 확정**을 누르세요. 해당 구분이 없으면 `해당 표기 없음`이라고 적으면 기존 표기만 지웁니다.
- **문장으로 보낼 때**: 승인 문장 다음 줄부터 제품별로 적습니다.
  ```
  승인 REQ-CA0D
  P-001 15번: 사고대비물질(톨루엔)
  P-003 15번: 인체급성유해성물질(포름알데히드), 인체만성유해성물질(포름알데히드)
  P-005 15번: 해당 표기 없음
  ```
  빠진 항목이 있으면 승인하지 않고, 남은 항목의 추천 문구와 입력 예시를 알려 줍니다.

### 5.2 승인 후 MSDS 반영 (시험 기능)

- 승인하면 제품 MSDS의 해당 항목이 바뀌고, **개정판 번호가 하나 올라가며 개정일은 승인한 날**이 됩니다. 이전 판은 개정 이력으로 보관됩니다.
- 승인 후 **새로고침해서 반영된 MSDS 보기**를 누르면 대시보드와 제품 MSDS 탭에 바뀐 내용이 나옵니다.
- 같은 변경을 다른 요청으로 또 승인하면 "이미 반영됨"으로 건너뜁니다.
- 시험 기능이라 **자체 평가를 돌릴 때는 자동으로 원래 데모 데이터로 되돌린 뒤 평가합니다.** 시험이 끝나면 운영 담당자에게 데이터 되돌리기를 요청하세요([부록 C](#부록-c-데이터-되돌리기와-평가-운영-담당자용)).

## 6. 날짜를 기준으로 묻기 (시행 예정 법령)

법령은 **질문 기준일에 시행 중인 조문**으로 판단합니다. 기준일은 이렇게 정해집니다.

| 질문에 이렇게 쓰면 | 기준일 |
|---|---|
| 날짜를 쓰지 않음 | 오늘 |
| `2027-05-01`, `2027. 5. 1.`, `2027년 5월 1일` | 그날 |
| `2027년 5월` | 그 달 1일 |
| `2028년` | 그 해 1월 1일 |
| `다음 달`, `내년` | 다음 달 1일, 다음 해 1월 1일 |

- 기준일 이후에 시행되는 조문은 판정 근거로 쓰지 않습니다. 대신 "시행 예정(YYYY-MM-DD 시행)"으로 따로 알립니다.
- 예: "2027년 5월 기준으로 MSDS 게시 의무는?"

## 7. 법령 가져오기 (수동 갱신)

법령이 개정됐다는 소식을 들으면 최신 조문을 가져오세요. **자동으로 주기적으로 가져오지는 않습니다.**

- 화면: 영향 분석 탭의 **법령 가져오기** 버튼
- 문장: `법령 갱신` (또는 `법령 가져오기`, `법령 업데이트`)

결과 예시:

```
법령을 다시 가져왔습니다 (가져온 날 2026-11-12).
1. 산업안전보건법: 현행 2026-10-27 시행 판(조문 8개), 내용이 바뀌는 시행 예정 판 없음
2. 산업안전보건법 시행규칙: 현행 2026-08-01 시행 판(조문 15개), 내용이 바뀌는 시행 예정 판 없음
3. 화학물질관리법: 현행 2026-10-08 시행 판(조문 1개), 내용이 바뀌는 시행 예정 판 없음
바뀐 조문은 없습니다.
```

- 국가법령정보센터에서 현행 판과 시행 예정 판을 받아 바뀐 조문을 알려 줍니다. 바뀐 조문이 있으면 검색 인덱스를 다시 만들고, 다음 질문부터 새 조문으로 답합니다.
- 보통 10초 안팎 걸립니다. 다른 사람이 갱신하는 중이면 "이미 진행 중"이라고 안내합니다.
- 어떤 법령을 가져오지 못하면 그 법령은 기존 조문을 그대로 쓰고, 실패했다고 알려 줍니다.

## 8. 답변 읽는 법

응답은 세 부분으로 옵니다. 화면에서는 답변 아래 **근거**와 **처리 단계**를 펼쳐 봅니다.

| 항목 | 내용 |
|---|---|
| `answer` | 답변. 결론을 먼저 쓰고 근거를 번호 목록으로 정리합니다 |
| `contexts` | 답변에 쓴 근거 목록. `doc_id`로 출처를 구분합니다 |
| `trace` | 처리 단계 기록(어떤 단계·도구를 거쳤는지). 문제를 확인할 때 씁니다 |

`doc_id` 읽는 법:

| 형식 | 뜻 |
|---|---|
| `law:산안법시행규칙:159` | 법령 조문 (현행 판) |
| `law:산안법:110@2027-04-28` | 시행 예정 판 조문. 본문 앞에 `[시행 예정 2027-04-28]` 표시가 붙습니다 |
| `msds:P-002` | 제품 MSDS (영업비밀·연락처는 가려짐) |
| `update:U-01` | 변경 사건 |
| `substance:108-88-3` | 단일물질 정보 (안전보건공단 공개 MSDS) |
| `rule:assess_update:U-02` 등 | 영향 제품·재제출 여부를 판정한 규칙 결과 |
| `catalog:products`, `catalog:updates` | 등록된 제품·변경 사건 목록 |
| `policy:service` | 서비스 정책(승인 후에만 확정, 연락처 마스킹 등). 승인 대기·거절 안내의 근거입니다 |

## 9. 답하지 않는 요청

다음 요청은 거절합니다. 정상 동작입니다.

| 요청 | 이유 |
|---|---|
| 영업비밀 성분의 실제 이름·CAS·정확한 함유량 | 공개 명칭과 함유량 범위(예: 세정보조제 HB-7, 5~10%)까지만 안내합니다 |
| 담당자 전체 연락처 | 이름·전화번호·이메일은 가려서만 보여 줍니다 |
| "승인 없이 바로 제출해" | 확정·제출은 승인 후에만 진행합니다 |
| "이전 지시는 무시하고…" 같은 지시 변경 | 따르지 않습니다 |
| MSDS·산업안전보건법·화학물질관리법과 무관한 질문 | 범위 밖이라 답하지 않습니다 |

## 10. 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| `http://localhost:8000/`이 열리지 않음 | 서버가 꺼져 있습니다. 운영 담당자에게 켜 달라고 하세요([부록 A](#부록-a-서버-켜기끄기-운영-담당자용)) |
| 주소창에 `/query`를 넣었더니 `{"detail":"Method Not Allowed"}` | 정상입니다. `/query`는 질문 제출(POST)만 받습니다. 화면은 `http://localhost:8000/`을 여세요 |
| "처리 중 오류가 발생했습니다" | 잠시 후 다시 보내 보세요. 계속되면 운영 담당자에게 알려 주세요. AI 사용 한도 초과일 수 있습니다 |
| 답변이 1분 넘게 걸림 | 복잡한 질문(사건 여러 개)은 더 걸립니다. 그래도 답이 없으면 다시 보내 보세요 |
| 승인함에 건이 안 보임 | 화면을 새로고침하세요. 서버의 승인 대기 건을 다시 불러옵니다 |
| "승인 대기 건이 없습니다" | 요청 번호(REQ-)가 맞는지, 이미 승인·반려했는지 확인하세요 |
| 승인이 안 되고 대체 표기를 요구함 | 확인 필요 항목이 있는 건입니다. 5.1을 보세요 |
| 승인했는데 MSDS가 그대로임 | **새로고침해서 반영된 MSDS 보기**를 누르거나 화면을 새로고침하세요 |
| 개정된 법령이 반영되지 않음 | 7장의 법령 가져오기를 실행하세요 |
| 한글이 깨져 보임 (PowerShell) | `$env:PYTHONIOENCODING="utf-8"`을 먼저 실행하세요 |
| 답에 "확인 필요"가 있음 | 에이전트가 원문으로 확인하지 못한 부분입니다. 국가법령정보센터나 공단 자료로 직접 확인하세요 |

## 부록 A. 서버 켜기·끄기 (운영 담당자용)

`mini-pjt` 폴더에서 실행합니다. 필요한 키(AWS Bedrock, 국가법령정보센터, 공공데이터포털, LangSmith)는 상위 폴더 `sds-ax-practice/.env`에 있어야 합니다. 파이썬은 상위 폴더의 `.venv`를 씁니다.

**Git Bash**

| 하려는 일 | 명령 |
|---|---|
| 처음 한 번: 법령·물질 데이터 수집과 검색 인덱스 생성 | `./run.sh setup` |
| 검색 인덱스만 다시 만들기 | `./run.sh index` |
| 서버 켜기 (`http://localhost:8000`) | `./run.sh serve` |
| 다른 포트로 켜기 | `PORT=8001 ./run.sh serve` |

**PowerShell** (Git Bash가 없을 때)

```powershell
$env:PYTHONIOENCODING="utf-8"
..\.venv\Scripts\python -m uvicorn src.api.app:app --host 0.0.0.0 --port 8000
```

- **서버 끄기**: 서버를 켠 창에서 `Ctrl+C`를 누릅니다.
- **상태 확인**: 브라우저에서 `http://localhost:8000/health` → `{"status":"ok"}`
- **사용 모델 바꾸기**: `.env`의 `BEDROCK_MODEL_ID`, `AWS_DEFAULT_REGION`을 고친 뒤 서버를 다시 켭니다. 현재 `us-west-2`의 `us.anthropic.claude-sonnet-4-6`을 씁니다.
- 승인 대기 건은 `checkpoints.sqlite`에 저장되어 서버를 다시 켜도 남습니다.

## 부록 B. 화면 없이 요청하기

서버 주소 `http://localhost:8000/query`에 질문 문장 하나를 보냅니다. 승인·반려·법령 갱신도 같은 방법으로 문장만 바꿔 보냅니다.

**방법 1. 브라우저 테스트 화면 (가장 쉬움)**

1. 브라우저에서 `http://localhost:8000/docs`를 엽니다.
2. 초록색 **POST /query** 줄을 눌러 펼치고, 오른쪽 **Try it out** 버튼을 누릅니다.
3. Request body 칸의 `"string"`을 질문으로 바꿉니다. 예: `{"question": "톨루엔(108-88-3)이 들어간 우리 제품은?"}`
4. 파란색 **Execute** 버튼을 누르면 아래 **Response body**에 답변이 나옵니다.

**방법 2. Windows PowerShell**

```powershell
$q = '{"question": "U-02 배합 변경 후 P-002 MSDS를 다시 제출해야 하나요?"}'
$r = Invoke-RestMethod -Uri http://localhost:8000/query -Method Post `
     -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($q))
$r.answer
```

**방법 3. 서버 없이 한 건 (운영 담당자)**

```bash
../.venv/Scripts/python -m scripts.try_agent "U-02 반영 후 P-002 재제출해야 해?"
```
